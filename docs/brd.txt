You need to create a completely new web application from scratch.

The project is a **Personal Budget Planner** вЂ” a web application for managing personal income, expenses, budgets, and financial history.

Do not start coding immediately. First understand the full project plan and requirements below, then implement the project step by step.

---

# 1. PROJECT IDEA

Create a web application where users can:

* register and log in;
* manage their personal income;
* manage their personal expenses;
* create, edit, and delete financial transactions;
* categorize income and expenses;
* set monthly budgets;
* track how much money they have spent;
* compare actual spending with planned budgets;
* view their current balance;
* view financial statistics;
* view transaction history;
* manage their profile.

The application should be simple, clean, modern, responsive, and easy to use.

Do not add unnecessary features that are not related to personal budget management.

Each user's financial data must be private and accessible only to that user.

---

# 2. USER ROLES

The application should have one main user type:

## Regular user

A registered user can:

* add income;
* add expenses;
* edit their own transactions;
* delete their own transactions;
* create and manage budgets;
* create and manage categories;
* view their current balance;
* view income and expense statistics;
* view transaction history;
* filter transactions;
* view monthly budget status;
* manage their profile;
* log out.

There does not need to be a separate administrator or financial advisor role.

Every registered user manages only their own personal financial information.

Create the following pages:

Show the user's current financial overview.

The dashboard should include:

* current balance;
* total income for the selected period;
* total expenses for the selected period;
* remaining budget;
* budget usage;
* recent transactions;
* current month overview;
* spending by category;
* quick action to add income;

* Income;

* filtering by category;

* description.

# 5. CATEGORY MANAGEMENT

Users should be able to organize transactions into categories.

At minimum, support separate categories for:

* income;
* expenses.

Allow users to:

* create categories;
* edit their own categories;
* delete their own categories where it is safe to do so.

A category that is already used by existing transactions should not be deleted in a way that would break historical financial data.

Validate category names and prevent inappropriate duplicate categories for the same user and transaction type.

---

# 6. TRANSACTION LOGIC

When creating a transaction:

1. User selects transaction type.
2. User enters the amount.
3. User selects a category.
4. User selects the date.
5. User optionally enters a description.
6. User saves the transaction.
7. The transaction becomes part of the user's financial history.
8. Dashboard statistics and balance are updated.

Validate all of these cases.

A transaction should not be created if:

* required fields are empty;
* amount is missing;
* amount is zero or negative;
* amount is not a valid number;
* category is invalid;
* date is invalid;
* the selected category does not belong to the current user;
* the submitted data is otherwise invalid.

---

# 7. BUDGET LOGIC

When creating a budget:

1. User selects an expense category.
2. User enters the planned amount.
3. User selects the budget period.
4. User specifies the relevant dates if required.
5. User saves the budget.
6. The application calculates actual spending for that category.
7. The application compares spending with the planned budget.
8. The dashboard displays the current budget status.

For each budget calculate:

* planned amount;
* spent amount;
* remaining amount;
* percentage used;
* budget status.

The spent amount must be based on the user's actual expense transactions belonging to the relevant category and period.

Do not use fake or hardcoded financial values.

---

# 8. DASHBOARD LOGIC

The dashboard should calculate financial information from persistent user data.

Current balance:

**Total Income - Total Expenses**

For a selected period, calculate:

* total income;
* total expenses;
* net balance;
* spending by category;
* budget usage.

Recent transactions should be loaded from the database/storage rather than hardcoded data.

When a transaction is created, edited, or deleted, the relevant dashboard information should update correctly.

# 11. SECURITY AND ACCESS CONTROL

Users must only be able to access and modify their own financial information.

Users must not be able to:

* view another user's transactions;
* edit another user's transactions;
* delete another user's transactions;
* view another user's budgets;
* edit another user's budgets;
* delete another user's budgets;
* modify another user's categories;
* access private profile information belonging to another user.

Validate permissions on the server/backend, not only in the frontend.

Do not trust data coming from the client.

Every database query involving personal financial information must respect the authenticated user's identity.

Never expose sensitive information unnecessarily.
