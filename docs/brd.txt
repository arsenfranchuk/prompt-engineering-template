# Personal Budget Planner — Master Project Prompt

## 1. Project Overview & Objective
Build and maintain **Personal Budget Planner**, a responsive, modern full-stack web application for personal financial management. The system allows individual users to track income and expenses, organize transactions into categories, establish and monitor monthly category budgets, and analyze financial health through dashboards and visual statistics. All user data is strictly private, secure, and isolated.

## 2. Technology Stack & Architectural Patterns
- **Backend**:
  - **Framework**: Python 3.12+ with FastAPI.
  - **Architecture**: Layered architecture (`routers` -> `services` -> `repositories` -> `models` -> `utils`).
  - **Data Persistence**: JSON file storage per entity (`backend/data/<entity>.json`) managed through repository abstractions.
  - **Validation & Schemas**: Pydantic v2 models.
  - **Authentication**: JWT (JSON Web Tokens) with OAuth2 Password Bearer flow and bcrypt password hashing.
  - **Package Management**: uv.
- **Frontend**:
  - **Framework**: React 18+ with TypeScript (Vite).
  - **UI & Styling**: Tailwind CSS, shadcn/ui component library, Lucide icons.
  - **State Management**: Redux Toolkit (RTK Query for API caching & invalidation, slices for client/auth state).
  - **Routing**: React Router v6 with declarative public and protected route guards.
- **Project Structure & Docs**:
  - Consolidated feature-oriented documentation under `docs/<feature>/` (business requirements, architecture, test cases).
  - Architecture conventions defined in `AGENTS.md`.

## 3. Core Functional Modules

### 3.1. Authentication & User Management (`/login`, `/register`, `/profile`)
- User registration with unique username and email, password confirmation, and secure bcrypt hashing.
- User authentication via JWT access tokens stored client-side and attached to all authenticated requests.
- Protected route wrapper redirecting unauthenticated users to `/login`.
- User profile page to review account details (username, email, creation date) and log out.

### 3.2. Category Management (`/categories`)
- Two distinct category types: `INCOME` and `EXPENSE`.
- Predefined system defaults alongside user-created custom categories.
- Full CRUD operations: create, edit, and safely delete categories.
- Safety check: prevent deletion of categories actively referenced in existing transactions or budgets.

### 3.3. Transaction Management (`/transactions`)
- Financial operations supporting `INCOME` (increases balance) and `EXPENSE` (decreases balance).
- Mandatory fields: amount (positive numeric), type, category, date, and optional description.
- Full CRUD capabilities via modal dialogs.
- Advanced querying: search by description, filter by type/category/date range, and sort by date or amount.

### 3.4. Budget Management (`/budgets`)
- Monthly budgets mapped to specific expense categories.
- Automatic computation of dynamic metrics:
  - Planned amount vs. actual spent amount (calculated from expense transactions in the period).
  - Remaining budget and percentage utilized.
  - Real-time status indicators: On Track (<80%), Warning (80–100%), Exceeded (>100%).
- Full CRUD support with validation to prevent overlapping or duplicate budgets for the same category and period.

### 3.5. Dashboard (`/dashboard`)
- Financial summary cards: Current Net Balance (`Total Income - Total Expenses`), Total Period Income, Total Period Expenses, and Remaining Budget.
- Category spending distribution and budget health indicators.
- Quick-action shortcuts (Add Income, Add Expense, Set Budget).
- Feed of recent transactions with direct navigation to full history.

### 3.6. Statistics & Analytics (`/statistics`)
- Historical financial breakdowns filtered by preset (current month, previous month, year-to-date) or custom date ranges.
- Visual breakdown of income vs. expenses over time.
- Category-level expenditure analysis.

## 4. Security & Data Integrity Requirements
- **Tenant Isolation**: Every financial record (`category`, `transaction`, `budget`) belongs to a specific `user_id`. Backend endpoints must enforce user ownership on every read, write, update, and delete operation.
- **Server-Side Validation**: Never rely solely on client-side validation. Enforce numeric constraints (positive amounts, valid date sequences), sanitize text inputs, and validate entity relationships.
- **Accurate Financial Arithmetic**: Ensure rounding and monetary conversions remain consistent and free of floating-point inaccuracies.

## 5. UI/UX Principles
- Modern, clean, and responsive design supporting desktop, tablet, and mobile viewports.
- Clear semantic color-coding: green for income/positive balances, red/destructive for expenses/exceeded budgets, amber for warnings.
- Explicit feedback states: loading spinners/skeletons, error alerts, empty state illustrations with calls-to-action, and delete confirmation dialogs.
